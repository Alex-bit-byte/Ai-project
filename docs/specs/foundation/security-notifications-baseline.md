# Базовая безопасность и локальные уведомления

Дата: 2026-05-11  
Статус: draft for human review  
PRD: `PRD-Semeynyy-Byudzhet-iOS-2026-05-11.md`  
Архитектура: `docs/architecture/ARCHITECTURE-MVP.md`

## 1. Контекст

MVP хранит финансовые данные локально и должен поддерживать Face ID / Touch ID, а также простые локальные напоминания о платежах. Эти возможности затрагивают приватность, поэтому базовые правила нужно зафиксировать до feature specs.

## 2. Цель

Определить системные политики для LocalAuthentication и UserNotifications без проектирования конкретных экранов.

## 3. Scope

Входит:

- LocalAuthentication;
- Face ID / Touch ID;
- fallback через системный код устройства;
- UserNotifications;
- нейтральный текст уведомлений;
- поведение при отказе в permissions.

Не входит:

- cloud accounts;
- собственная авторизация;
- пароли внутри приложения;
- шифрование отдельным ключом приложения;
- раскрывающие push-тексты с суммой и названием кредита;
- сложные сценарии повторных уведомлений.

## 4. Security requirements

- Биометрическая защита выключена по умолчанию, пока пользователь не включит ее в настройках.
- При включенной защите приложение требует системную локальную аутентификацию при открытии.
- Если биометрия недоступна, приложение должно объяснить причину и предложить системный fallback, если он доступен.
- Приложение не должно отправлять финансовые данные на внешний сервер.
- Domain и Data layers не должны зависеть от LocalAuthentication.

## 5. Notification requirements

- Уведомления локальные и используют UserNotifications.
- Разрешение на уведомления запрашивается в контексте включения напоминаний.
- Если пользователь отказал в разрешении, приложение продолжает работать без уведомлений.
- Уведомление по умолчанию использует нейтральный текст: "Напоминание о платеже".
- По умолчанию уведомление не содержит сумму, название кредита и имя участника.

## 6. Acceptance criteria

- Security flow не блокирует приложение, если пользователь не включал защиту.
- При включенной защите используется системный LocalAuthentication flow.
- Отказ в notification permission не ломает создание кредита или платежей.
- Тексты уведомлений не раскрывают финансовые детали по умолчанию.
- Системные permissions не запрашиваются без пользовательского намерения.

## 7. UI states

Конкретные UI-состояния будут описаны в feature specs для Settings, Security и Notifications.

Минимально должны быть учтены:

- защита выключена;
- защита включена;
- биометрия недоступна;
- аутентификация успешна;
- аутентификация отменена;
- notification permission не запрошен;
- notification permission granted;
- notification permission denied.

## 8. Edge cases

- На устройстве нет Face ID / Touch ID.
- Пользователь отменил аутентификацию.
- Устройство не имеет passcode fallback.
- Пользователь запретил уведомления в системных настройках.
- Пользователь изменил дату платежа после планирования уведомления.
- Пользователь отключил reminder для кредита после планирования уведомления.

## 9. Модель данных

Базовые settings:

- `biometricLockEnabled: Bool`
- `notificationsEnabled: Bool`

Для кредита:

- `reminderEnabled: Bool`
- `paymentDay: Int`

Конкретные identifiers для scheduled notifications должны быть описаны в notification feature spec.

## 10. Миграции

Не требуются до появления SwiftData schema.

## 11. Стратегия тестирования

- Unit tests для Application-level state decisions.
- Manual checks на simulator/device для LocalAuthentication behavior.
- Manual checks для notification permission flow.
- Tests для генерации stable notification identifiers после появления notification scheduling spec.

## 12. Принятые базовые допущения

- В MVP используется только нейтральный текст уведомления без суммы, названия кредита и имени участника.
- Повторная аутентификация требуется при cold start и при возвращении из background после паузы более 5 минут, если biometric lock включен.
