# Участники семьи

Дата: 2026-05-11  
Статус: draft for human review  
PRD: `PRD-Semeynyy-Byudzhet-iOS-2026-05-11.md`  
Архитектура: `docs/architecture/ARCHITECTURE-MVP.md`

## 1. Контекст

Участники семьи являются базовой сущностью для доходов, кредитов и индивидуальных расчетов. Без участника нельзя создать доход или кредит.

## 2. Цель

Позволить пользователю создавать, редактировать, просматривать и удалять участников семьи с защитой от случайной потери связанных данных.

## 3. Пользовательские сценарии

- Пользователь добавляет первого участника семьи.
- Пользователь редактирует имя участника.
- Пользователь пытается удалить участника, у которого есть доходы или кредиты, и видит предупреждение.

## 4. Functional requirements

- Участник имеет обязательное имя.
- Имя не должно быть пустым после trimming whitespace.
- Пользователь может создать минимум одного участника.
- Пользователь может редактировать имя участника.
- Пользователь может удалить участника.
- Удаление участника со связанными доходами или кредитами требует явного подтверждения.
- После удаления участника связанные данные обрабатываются по правилу, заданному task для реализации: cascade delete после подтверждения.

## 5. Acceptance criteria

- Нельзя сохранить участника с пустым именем.
- Созданный участник доступен в списках выбора владельца дохода и кредита.
- Изменение имени отражается во всех UI-местах, где показывается участник.
- Удаление участника без связанных данных выполняется после обычного подтверждения.
- Удаление участника со связанными данными показывает предупреждение о потере доходов, кредитов и платежей.

## 6. UI states

- список пуст;
- список участников;
- форма создания;
- форма редактирования;
- validation error для имени;
- confirmation dialog удаления;
- destructive confirmation для удаления со связанными данными.

## 7. Ошибки и edge cases

- одинаковые имена участников;
- очень длинное имя;
- удаление последнего участника;
- удаление участника, открытого на другом экране;
- persistence error при сохранении или удалении.

## 8. Модель данных

`FamilyMember`:

- `id: UUID`
- `name: String`
- `createdAt: Date`
- `updatedAt: Date`

Связи:

- has many `Income`
- has many `Credit`

## 9. Миграции

Не требуются для первой версии.

## 10. Стратегия тестирования

- Unit tests для validation имени.
- Repository/in-memory persistence tests для create, update, delete.
- ViewModel state tests для пустого списка, ошибок и подтверждения удаления.

## 11. Принятые базовые допущения

- Одинаковые имена участников разрешены, потому что уникальность имени не является доменным требованием.
