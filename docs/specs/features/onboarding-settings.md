# Первый запуск и настройки валюты

Дата: 2026-05-11  
Статус: draft for human review  
PRD: `PRD-Semeynyy-Byudzhet-iOS-2026-05-11.md`  
Архитектура: `docs/architecture/ARCHITECTURE-MVP.md`

## 1. Контекст

MVP хранит данные локально и использует одну основную валюту. До создания денежных записей пользователь должен иметь понятный способ подтвердить или изменить валюту.

## 2. Цель

Обеспечить базовый первый запуск и экран настроек, где пользователь видит валюту, параметры защиты, уведомления и информацию о приложении.

## 3. Пользовательские сценарии

- Пользователь впервые открывает приложение и видит пустое состояние с предложением настроить семью.
- Пользователь открывает настройки и выбирает основную валюту до создания денежных записей.
- Пользователь видит, что после появления денежных записей валюта заблокирована до отдельного future spec.

## 4. Functional requirements

- Приложение должно создать default `AppSettings`, если запись отсутствует.
- Настройки должны показывать текущий `currencyCode`.
- Основную валюту можно изменить только если еще нет денежных записей.
- Настройки должны содержать toggles для Face ID / Touch ID и уведомлений, но детальное поведение описывается в `app-security.md` и `local-payment-reminders.md`.
- Экран настроек должен показывать информацию о приложении: название, версия, локальный-only storage note.

## 5. Acceptance criteria

- При первом запуске приложение имеет валидные настройки.
- Пользователь может увидеть текущую валюту.
- Пользователь может изменить валюту до создания доходов или кредитов.
- После создания денежных записей изменение валюты заблокировано или требует будущего spec.
- Настройки не создают внешних аккаунтов и не требуют сети.

## 6. UI states

- первый запуск без данных;
- настройки загружены;
- валюта доступна для изменения;
- валюта заблокирована из-за существующих денежных записей;
- пустое состояние семьи;
- ошибка загрузки настроек.

## 7. Ошибки и edge cases

- `AppSettings` отсутствует;
- существует больше одной записи settings;
- выбранный `currencyCode` пустой или невалидный;
- пользователь пытается изменить валюту после создания денежных записей.

## 8. Модель данных

Используется `AppSettings`:

- `currencyCode: String`
- `biometricLockEnabled: Bool`
- `notificationsEnabled: Bool`

## 9. Миграции

Не требуются для первой версии.

## 10. Стратегия тестирования

- Unit tests для default settings initialization.
- Tests для блокировки изменения валюты при наличии денежных записей.
- ViewModel state tests для states настроек.

## 11. Открытые вопросы
