# Детали месяца и оплата платежей

Дата: 2026-05-11  
Статус: draft for human review  
PRD: `PRD-Semeynyy-Byudzhet-iOS-2026-05-11.md`  
Архитектура: `docs/architecture/ARCHITECTURE-MVP.md`

## 1. Контекст

Годовая таблица показывает только семейные итоги. Детали месяца нужны, чтобы пользователь понял состав доходов, платежей и остатков по каждому участнику.

## 2. Цель

Показать детализацию выбранного месяца и дать пользователю отметить платеж как оплаченный.

## 3. Пользовательские сценарии

- Пользователь открывает детали месяца из годовой таблицы.
- Пользователь видит доходы, платежи и остаток по каждому участнику.
- Пользователь видит список платежей месяца.
- Пользователь отмечает платеж как оплаченный.
- Пользователь видит просроченные неоплаченные платежи.

## 4. Functional requirements

- Экран получает выбранный `YearMonth`.
- Экран показывает общую сводку семьи за месяц.
- Экран показывает список участников с доходами, платежами и остатками.
- Экран показывает список платежей месяца.
- Пользователь может отметить planned/overdue платеж как paid.
- При оплате платеж получает `status: paid` и `paidAt`.
- Просроченность определяется относительно текущей даты и due date.
- Оплаченный платеж не считается просроченным.

## 5. Acceptance criteria

- Для каждого участника считается доход, платежи и остаток.
- Общая сводка совпадает с годовой таблицей для того же месяца.
- Платеж можно отметить как оплаченный.
- После отметки оплаты статус меняется и сохраняется.
- Просроченные неоплаченные платежи выделяются.
- Нельзя повторно оплатить уже оплаченный платеж без отдельного undo/edit spec.

## 6. UI states

- месяц без данных;
- месяц с доходами без платежей;
- месяц с платежами без доходов;
- нормальный месяц;
- месяц с отрицательным остатком;
- платеж planned;
- платеж paid;
- платеж overdue;
- saving state при отметке оплаты;
- ошибка сохранения оплаты.

## 7. Ошибки и edge cases

- участник удален, но остались платежи в поврежденном persistence state;
- due date сегодня;
- due date в прошлом;
- `paidAt` в будущем;
- быстрые повторные нажатия на оплату;
- ошибка сохранения после изменения статуса.

## 8. Модель данных

Использует:

- `FamilyMember`
- `Income`
- `IncomeOverride`
- `Credit`
- `CreditPayment`
- `MonthlyBudgetSummary`
- `PaymentStatus`

## 9. Миграции

Не требуются.

## 10. Стратегия тестирования

- Domain tests для overdue detection.
- Domain/Application tests для month details summary.
- Use case tests для mark payment as paid.
- ViewModel state tests для payment status transitions.
- UI happy path для отметки оплаты.

## 11. Принятые базовые допущения

- Отмена оплаты платежа не входит в MVP, чтобы не расширять scope.
