# Главная годовая таблица

Дата: 2026-05-11  
Статус: draft for human review  
PRD: `PRD-Semeynyy-Byudzhet-iOS-2026-05-11.md`  
Архитектура: `docs/architecture/ARCHITECTURE-MVP.md`

## 1. Контекст

Главная годовая таблица заменяет текущую Numbers/Excel-таблицу на iPhone. Она должна быть компактной и показывать семейные итоги по каждому месяцу.

## 2. Цель

Показать 12 месяцев выбранного года с общим доходом семьи, кредитной нагрузкой, остатком "на жизнь", процентом нагрузки и статусной индикацией.

## 3. Пользовательские сценарии

- Пользователь открывает приложение и видит текущий год.
- Пользователь переключает год вперед или назад.
- Пользователь видит тяжелые месяцы по цветовой индикации.
- Пользователь нажимает на месяц и переходит в детали.

## 4. Functional requirements

- Экран показывает календарный год из 12 месяцев.
- По каждому месяцу рассчитываются:
  - общий доход семьи;
  - общая сумма кредитных платежей;
  - остаток на жизнь;
  - процент кредитной нагрузки;
  - агрегированный статус платежей месяца.
- Пользователь может переключать выбранный год.
- Кредиты за пределами текущего года отображаются в соответствующих будущих годах.
- Цвет нагрузки:
  - до 30%: зеленый;
  - 30-50%: желтый;
  - выше 50%: красный;
  - `notApplicable` при нулевом доходе: нейтральное/предупреждающее состояние, не зеленый.

## 5. Acceptance criteria

- Годовая таблица показывает 12 месяцев.
- Итоги пересчитываются после изменения доходов, кредитов или платежей.
- Остаток считается как доход семьи минус кредитная нагрузка.
- Процент нагрузки не делит на ноль.
- Нажатие на месяц открывает flow деталей месяца, описанный в `month-details-payments.md`.
- Таблица не перегружена деталями по каждому человеку.

## 6. UI states

- нет участников;
- есть участники, но нет доходов и кредитов;
- год с данными;
- год без данных;
- месяц с нормальной нагрузкой;
- месяц с высокой нагрузкой;
- месяц с просроченными платежами;
- ошибка расчета или загрузки.

## 7. Ошибки и edge cases

- доход равен нулю;
- нагрузка больше дохода;
- отрицательный остаток;
- год далеко в будущем;
- год далеко в прошлом;
- кредиты, начавшиеся в одном году и заканчивающиеся в другом;
- все платежи оплачены;
- есть просроченные платежи.

## 8. Модель данных

Использует read models/application view state:

- `YearlyOverviewState`
- `MonthlyBudgetSummary`
- `CreditLoadPercentage`
- `PaymentMonthStatus`

Точные имена могут быть уточнены в tasks, но расчеты должны опираться на Domain.

## 9. Миграции

Не требуются.

## 10. Стратегия тестирования

- Domain tests для monthly summary.
- Application tests для yearly overview из 12 месяцев.
- Tests для thresholds 30% и 50%.
- ViewModel state tests для empty/data/error states.
- UI happy path для перехода в детали месяца.

## 11. Принятые базовые допущения

- `notApplicable` при нулевом доходе показывается нейтральным серым статусом с текстом "нет дохода".
