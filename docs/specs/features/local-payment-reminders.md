# Локальные напоминания о платежах

Дата: 2026-05-11  
Статус: draft for human review  
PRD: `PRD-Semeynyy-Byudzhet-iOS-2026-05-11.md`  
Базовый spec: `docs/specs/foundation/security-notifications-baseline.md`

## 1. Контекст

MVP должен напоминать пользователю о кредитных платежах локально на устройстве. Уведомления не должны раскрывать финансовые детали по умолчанию.

## 2. Цель

Позволить включать и выключать локальные напоминания для кредитов, планировать уведомления и корректно обрабатывать отказ в разрешении.

## 3. Пользовательские сценарии

- Пользователь включает уведомления в настройках.
- Пользователь включает reminder для конкретного кредита.
- Приложение запрашивает permission в контексте включения уведомлений.
- Пользователь получает нейтральное локальное уведомление перед датой платежа.
- Пользователь отключает reminder, и будущие уведомления отменяются.

## 4. Functional requirements

- Уведомления используют UserNotifications.
- Permission запрашивается только после пользовательского намерения.
- Если permission denied, приложение продолжает работать без уведомлений.
- Reminder можно включить/выключить на уровне кредита.
- Текст уведомления по умолчанию: "Напоминание о платеже".
- Уведомление не содержит сумму, название кредита или имя участника.
- При изменении `paymentDay`, срока или графика кредита связанные уведомления должны быть перепланированы.
- При удалении кредита связанные уведомления должны быть отменены.

## 5. Acceptance criteria

- Пользователь может включить глобальные уведомления.
- Пользователь может включить reminder для кредита.
- Permission denied не блокирует создание кредита.
- Scheduled notification identifiers стабильны и позволяют отменять уведомления кредита.
- Отключение reminder отменяет будущие уведомления.
- Уведомления не раскрывают финансовые детали.

## 6. UI states

- notifications disabled in app;
- permission notDetermined;
- permission granted;
- permission denied;
- reminder disabled for credit;
- reminder enabled for credit;
- scheduling failed;
- notification scheduled.

## 7. Ошибки и edge cases

- пользователь запретил уведомления в системных настройках;
- пользователь включил reminder до выдачи permission;
- кредит изменен после планирования уведомлений;
- кредит удален после планирования уведомлений;
- due date уже прошел;
- слишком много будущих уведомлений;
- приложение не может прочитать notification settings.

## 8. Модель данных

`AppSettings`:

- `notificationsEnabled: Bool`

`Credit`:

- `reminderEnabled: Bool`
- `paymentDay: Int`

Notification identifier должен строиться стабильно из `creditId` и `paymentId` или `creditId` + `YearMonth`.

## 9. Миграции

Не требуются.

## 10. Стратегия тестирования

- Unit tests для генерации notification identifiers.
- Application tests для schedule/cancel decisions.
- Manual checks для permission flow.
- Manual checks для получения локального уведомления.

## 11. Принятые базовые допущения

- Напоминание создается за 1 день до due date в 09:00 локального времени.
