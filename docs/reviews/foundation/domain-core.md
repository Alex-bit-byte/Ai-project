# Review: доменное ядро

Дата: 2026-05-11  
Task: `docs/tasks/foundation/domain-core.md`  
Spec: `docs/specs/foundation/domain-core.md`  
Статус: implementation review, ожидает XCTest в полном Xcode

## Соответствие spec

- `Money` хранит `Decimal` и `currencyCode`, не использует `Double` для доменной арифметики.
- Денежная арифметика запрещает смешивание валют через `MoneyError.currencyMismatch`.
- `YearMonth` валидирует месяц, поддерживает сортировку, переходы и диапазоны.
- Реализованы базовые entities и enums для участников, доходов, кредитов и платежей.
- Повторяющиеся и разовые доходы рассчитываются по `YearMonth`.
- `IncomeOverride` заменяет сумму повторяющегося дохода в конкретном месяце.
- График платежей кредита создается в пределах `termMonths`; `paymentDay` больше длины месяца переносится на последний день месяца.
- Реализованы расчет дохода участника/семьи, кредитной нагрузки, остатка и процента нагрузки.
- При нулевом доходе процент нагрузки возвращает `CreditLoadPercentage.notApplicable`.
- Domain не импортирует SwiftUI и SwiftData.

## Найденные риски

- XCTest не был запущен из-за отсутствия полного Xcode в текущем окружении.
- Текущая модель `PaymentStatus` минимальна: `scheduled`, `paid`, `skipped`. Если feature specs потребуют больше статусов, это нужно расширять отдельной задачей.
- Политика округления процентов кредитной нагрузки пока не задана; сейчас возвращается raw `Decimal`.
- `paymentDay` валидируется как `1...31`, а календарное приведение к последнему дню месяца выполняется при генерации due date.

## Тестовые пробелы

- Тесты добавлены, но фактический XCTest-прогон требует полного Xcode.
- Нет теста на округление процентов, потому что политика округления не определена в spec.

## Ручные проверки

- Выполнен `swiftc -typecheck` для Domain Swift-файлов.
- Проверено, что Domain не импортирует SwiftUI или SwiftData.
- Проверен синтаксис `project.pbxproj` и shared scheme.
